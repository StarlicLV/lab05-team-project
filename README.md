## Опис

REST API до вебзастосунку кав'ярні з лабораторної роботи 4 (Flask + SQLite). API повертає дані у форматі JSON,
використовує HTTP-методи за призначенням (GET, POST, PUT, PATCH, DELETE) та відповідні коди статусу.

**Технології:** Python, Flask, SQLite, flasgger (Swagger UI), Postman.

## Запуск

```bash
python -m venv .venv
.venv\Scripts\activate          # Windows
pip install -r requirements.txt
python app.py
```

API доступне за адресою `http://127.0.0.1:5000/api`, документація: `http://127.0.0.1:5000/apidocs/`.

## Структура API

```text
api/
├── __init__.py      підключення API до застосунку (register_api)
├── errors.py        єдиний формат помилок, JSON-обробники
├── utils.py         читання JSON, валідація полів, пагінація
├── docs.py          Swagger UI (flasgger), запасна сторінка /apidocs/
├── v1/              products.py, orders.py, customers.py
└── v2/              products.py, customers.py
tests/
└── test_api.py      автотести (unittest)
docs/
└── test-report.md   звіт про тестування
postman_collection.json   повна колекція Postman (63 запити з тестами)
postman_orders.json       колекція модуля замовлень
```

Кожен учасник працює у власному файлі (окремий Blueprint), версії API підключені через `url_prefix`: `/api/v1`, `/api/v2`.

## Ендпоінти

### Клієнти, v1 (`/api/v1/customers`)

| Метод | Адреса | Призначення | Коди відповідей |
|---|---|---|---|
| GET | `/api/v1/customers` | список клієнтів | 200 |
| GET | `/api/v1/customers/<id>` | один клієнт | 200, 404 |
| GET | `/api/v1/customers/<id>/orders` | замовлення клієнта | 200, 404 |
| POST | `/api/v1/customers` | створити клієнта | 201, 400, 409, 415 |
| PUT | `/api/v1/customers/<id>` | повна заміна даних | 200, 400, 404, 409 |
| PATCH | `/api/v1/customers/<id>` | часткове оновлення | 200, 400, 404, 409 |
| DELETE | `/api/v1/customers/<id>` | видалити клієнта | 204, 404, 409 |

### Клієнти, v2 (`/api/v2/customers`)

| Метод | Адреса | Призначення | Коди відповідей |
|---|---|---|---|
| GET | `/api/v2/customers?page=&per_page=&q=&sort=&order=` | список із пагінацією, пошуком і сортуванням | 200, 400 |
| GET | `/api/v2/customers/<id>` | клієнт із замовленнями й сумою витрат | 200, 404 |

### Товари, v1 (`/api/v1/products`)

| Метод | Адреса | Призначення | Коди відповідей |
|---|---|---|---|
| GET | `/api/v1/products?category=&q=&available=` | список товарів із фільтрами | 200, 400 |
| GET | `/api/v1/products/categories` | список категорій | 200 |
| GET | `/api/v1/products/<id>` | один товар | 200, 404 |
| POST | `/api/v1/products` | створити товар (`name`, `price`, `category`) | 201, 400, 415 |
| PUT | `/api/v1/products/<id>` | повна заміна товару | 200, 400, 404, 415 |
| PATCH | `/api/v1/products/<id>` | часткове оновлення | 200, 400, 404, 415 |
| DELETE | `/api/v1/products/<id>` | видалити товар | 204, 404, 409 |

### Товари, v2 (`/api/v2/products`)

| Метод | Адреса | Призначення | Коди відповідей |
|---|---|---|---|
| GET | `/api/v2/products?page=&per_page=&sort=&q=&category=&min_price=&max_price=&available=` | список із пагінацією, сортуванням і фільтрами | 200, 400 |
| GET | `/api/v2/products/<id>` | один товар у форматі `{"data": ...}` | 200, 404 |

### Замовлення, v1 (`/api/v1/orders`)

| Метод | Адреса | Призначення | Коди відповідей |
|---|---|---|---|
| GET | `/api/v1/orders?status=` | список замовлень (фільтр за статусом) | 200, 400 |
| GET | `/api/v1/orders/<id>` | замовлення з позиціями | 200, 404 |
| POST | `/api/v1/orders` | створити замовлення (необовʼязковий `promo_code`) | 201, 400, 404, 415 |
| PATCH | `/api/v1/orders/<id>/status` | змінити статус | 200, 400, 404, 415 |

Статуси замовлення: `new`, `preparing`, `delivering`, `done`, `cancelled`. Промокоди: `SWEET10` (−10%), `WELCOME15` (−15%). Ціни беруться з бази, а не із запиту.

## Формат помилок

Усі помилки на адресах `/api/...` повертаються у JSON (сторінки сайту лишаються HTML):

```json
{"error": "Помилка валідації даних", "status": 400, "details": {"phone": "Поле обовʼязкове"}}
```

| Код | Коли |
|---|---|
| 400 | некоректні дані: помилка валідації, зламаний JSON, неправильний параметр запиту |
| 404 | ресурс не знайдено (або неіснуюча адреса) |
| 405 | метод не дозволений для адреси |
| 409 | конфлікт: телефон уже існує, видалення клієнта із замовленнями |
| 415 | тіло запиту не є JSON (`Content-Type: application/json`) |
| 500 | внутрішня помилка сервера |

## Валідація

- `name` обовʼязкове, рядок, до 100 символів;
- `phone` обовʼязкове, 10–13 цифр (пробіли, дужки й дефіси прибираються), унікальне;
- `email` необовʼязкове, формат `a@b.c`;
- товар: `name` і `category` — рядки до 100 символів, `price` — число ≥ 0 (не рядок і не `true`), `is_available` — `true`/`false`;
- замовлення: `customer_id`, `address`, непорожній список `items` із `product_id` і `quantity` (цілі числа > 0);
- тіло запиту має бути JSON-обʼєктом; помилки по полях повертаються в `details`.

## Версії API

- **v1** повертає простий список: `{"customers": [...]}`.
- **v2** додає пагінацію (`page`, `per_page` до 100), пошук (`q`), сортування (`sort`, `order`), відповідь у вигляді `{"data": [...], "meta": {...}}`, а картка клієнта містить вкладені замовлення й `total_spent`.

## Результати тестування

Детальний звіт зі списком усіх сценаріїв: [`docs/test-report.md`](docs/test-report.md).

### Автотести (unittest)

```bash
python -m unittest discover -s tests -v
```

**Результат:** `Ran 83 tests ... OK`. Тести покривають усі endpoints v1 і v2: успішні запити, валідацію, коди 400 / 404 / 405 / 409 / 415 та формат JSON-помилок. Кожен тест працює з тимчасовою базою, тому реальний `db.sqlite` не змінюється.

### Postman

1. Запустіть застосунок: `python app.py`.
2. У Postman: **Import** → `postman_collection.json` (змінна колекції `base` = `http://127.0.0.1:5000`).
3. Натисніть **Run collection** і запустіть усі 63 запити підряд (порядок важливий: `id` створених ресурсів передаються далі через змінні).

Для кожного запиту є скрипт `pm.test` (код відповіді, формат JSON, ключові поля). У колекції є і успішні запити, і запити з помилками (неіснуючий id, порожні поля, некоректні параметри).
